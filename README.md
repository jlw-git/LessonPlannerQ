# Lesson Planner Q

AI-powered lesson preparation studio for Chinese Mahayana folk Buddhist educators teaching small 90-minute classes of 13-year-old students.

## What It Does

- Generates weekly 90-minute lesson plans.
- Reviews and revises lesson options, lesson briefs, and full lesson plans with bounded pedagogy and tradition review loops.
- Supports play-based learning and scaffolded self-directed learning.
- Provides an educator rehearsal coach for difficult student questions.
- Critiques typed educator rehearsal attempts for clarity, tone, age fit, and doctrinal caution.
- Creates visual-pack prompts, story cards, scenario cards, and reflection worksheet prompts.
- Can generate lesson visuals with GPT Image 2.
- Prints or saves lesson plan drafts and visual packs as PDFs through the browser print dialog.
- Includes a Realtime 2 voice-first planning path where the educator can talk about lesson requirements.
- Keeps the latest voice transcript reviewable after the voice session ends, with local browser storage and a copy action.
- Extracts voice transcripts into editable planning fields for educator review before generation.
- Synthesizes saved reflections into inspectable classroom evidence and tracks local-only planning signals in browser storage.

## LLM vs Rules-Based Behavior

Lesson Planner Q combines model-generated drafts with deterministic application logic.

LLM-backed:

- Lesson options, lesson briefs, brief updates, full lesson plans, visual material packs, rehearsal coaching, rehearsal critique, and reflection synthesis are generated by the OpenAI Responses API using strict JSON schemas.
- Lesson options, lesson briefs, and full lesson plans run through draft, review, and one-pass revision loops before display; the UI shows returned `optionReview` and `agentReview` notes for educator review.
- Lesson images are generated by the OpenAI Images API from educator-reviewed visual prompts.
- Voice planning uses OpenAI Realtime sessions for educator-facing planning conversations only; drafting happens after educator approval.
- Voice extraction uses the Responses API to turn transcripts into reviewed form context; it does not directly generate an authoritative lesson.

Rules-based or app-controlled:

- Workflow order, selected option state, form defaults, loading states, and the educator review flow are handled in React.
- Extracted voice fields are reviewed and approved by the educator before existing option and brief generation flows use them.
- The latest voice transcript is saved locally in the browser under `lesson-planner-q-last-voice-transcript`, remains reviewable after ending or refreshing, and is cleared when a new voice session starts.
- Reflection memory is saved, edited, deleted, capped, synthesized, and loaded from browser `localStorage`; the app sends recent reflections plus inspectable synthesis to generation routes as context.
- Print/save-as-PDF uses browser print CSS, not a generated binary PDF service.
- Planning metrics are local-only browser events and are not sent to an analytics provider.
- API routes, schema enforcement, prompt-cache configuration, health checks, and error handling are implemented in the Express server.
- Local eval graders check schemas and product guardrails with deterministic code, even though the evaluated outputs come from LLM-backed routes.

## Setup

1. Install dependencies:

```bash
npm install
```

2. Create `.env.local` from `.env.example` and add your OpenAI API key.

   Prompt caching is enabled automatically for repeated OpenAI text requests. Keep `OPENAI_PROMPT_CACHE_RETENTION=in_memory` for the default cache behavior, or set it to `24h` if your selected model supports extended prompt cache retention. Set `LOG_PROMPT_CACHE=1` while developing to print cached input token counts for each text generation route.

3. Start the app:

```bash
npm run dev
```

The web app runs at [http://127.0.0.1:5173](http://127.0.0.1:5173), and the API runs at `http://127.0.0.1:8787`.

## Permissions

Realtime voice planning may ask the browser for microphone access. Lesson Planner Q does not need system screen recording permission and does not capture the screen. If you do not want to grant microphone access, use typed planning instead.

## Evals

Run the local agent-behavior evals with:

```bash
npm run eval:local
```

The evals call the real API routes and require `OPENAI_API_KEY`. Results are written to `evals/results/latest.json`.
